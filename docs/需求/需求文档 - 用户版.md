# Termy 远程终端增强需求文档（用户版）

  

> **V1 一句话说明**：在 Windows 的 Obsidian Termy 中，连接本人另一台 Windows 电脑或无桌面的 Ubuntu 服务器，并把当前笔记及直接附件发送过去。

  

| 控制端 | 目标端 | 当前版本 |

| --- | --- | --- |

| Windows + Obsidian Desktop + 增强版 Termy | Windows Agent 或无桌面 Ubuntu Agent | V1 |

  

 [[终端插件/需求文档|需求文档]] · [[实现方案 - 开发版]]

  

## 1. 一眼看懂

  

```mermaid

flowchart LR

    U[用户]

    subgraph A[设备 A：Windows 控制端]

        O[Obsidian]

        T[增强版 Termy]

        N[笔记与附件]

        O --> T

        N --> T

    end

  

    C[云端中继]

  

    subgraph B[设备 B：目标端]

        AG[Termy Agent]

        SH[PowerShell 或 Bash]

        F[接收目录]

        AG --> SH

        AG --> F

    end

  

    U --> T

    T <-->|TLS：终端与文件| C

    C <-->|TLS| AG

```

  

设备 B 可以是：

  

- Windows 电脑，运行 `termy-agent.exe`；

- 没有桌面环境的 Ubuntu 服务器，运行命令行程序 `termy-agent`。

  

设备 B **不需要安装或打开 Obsidian**，也不需要公网 IP 或开放入站端口。

  

## 2. 首次配对

  

```mermaid

sequenceDiagram

    autonumber

    actor User as 用户

    participant A as Windows Termy

    participant Cloud as 云端服务

    participant B as 目标端 Agent

  

    User->>A: 登录账号，选择“添加目标设备”

    A->>Cloud: 申请一次性配对码

    Cloud-->>A: 显示长期有效配对码

    User->>B: termy-agent bind --code 配对码

    B->>Cloud: 消费配对码并登记设备

    Cloud-->>A: 设备显示“在线”

```

  

目标端只需：**安装 Agent → 输入配对码 → 设置接收目录 → 启动 Agent**。

  

配对码生成后长期有效，首次成功绑定后立即生效；用户也可以在设备 A 主动撤销尚未使用的配对码。

  

Ubuntu Agent 通过用户级 `systemd` 运行。退出 SSH 后仍保持在线，但 Agent 和远端 Shell 都以普通用户身份运行，不使用 root。

  

## 3. 日常使用

  

```mermaid

flowchart LR

    OPEN[打开 Termy]

    MODE[切换到远程]

    DEVICE[选择在线设备]

    CONNECT[连接]

    USE{要做什么?}

    CMD[输入终端命令]

    DROP[拖入一篇 Markdown]

    RESULT[查看输出或传输结果]

    CLOSE[断开]

  

    OPEN --> MODE --> DEVICE --> CONNECT --> USE

    USE -->|操作电脑| CMD --> RESULT

    USE -->|发送资料| DROP --> RESULT

    RESULT --> USE

    USE -->|结束| CLOSE

```

  

```mermaid

stateDiagram-v2

    [*] --> 本地模式

    本地模式 --> 未连接: 切换到远程

    未连接 --> 连接中: 选择在线设备

    连接中 --> 已连接: 连接成功

    连接中 --> 连接失败: 连接异常

    已连接 --> 传输中: 拖入笔记

    传输中 --> 已连接: 成功或失败

    已连接 --> 已断开: 主动断开

    已连接 --> 连接失败: 网络中断

    连接失败 --> 连接中: 手动重连

```

  

| 当前状态 | 命令输入 | 拖入笔记 | 用户操作 |

| --- | --- | --- | --- |

| 本地模式 | 可用 | 保持原有行为 | 使用本机终端 |

| 未连接 / 连接中 | 禁用 | 禁用 | 选择设备或等待 |

| 已连接 | 可用 | 可用 | 操作远端或断开 |

| 传输中 | 可用 | 不可重复拖入 | 等待整次结果 |

| 连接失败 / 已断开 | 禁用 | 禁用 | 手动重新连接 |

  

V1 断线后不会自动重连，也不会缓存断线期间的输入。

  

## 4. 笔记怎样发送

  

```mermaid

flowchart LR

    NOTE[一篇 Markdown 笔记]

    CACHE[识别直接引用]

    SET[笔记 + Vault 内本地附件]

    SEND[云端实时中转]

    WRITE[按 Vault 相对路径写入]

    DONE{整次结果}

  

    NOTE --> CACHE --> SET --> SEND --> WRITE --> DONE

    DONE -->|成功| OK[显示文件数与保存目录]

    DONE -->|失败| FAIL[显示原因]

```

  

| 会发送 | 不会发送 |

| --- | --- |

| 一篇从文件列表拖入的 `.md` 笔记 | 被链接 Markdown 的下一层附件 |

| 该笔记直接引用的 Vault 内图片、PDF、音频等 | 外部网络资源、整个目录、多篇笔记 |

  

远程模式不会把设备 A 的本地绝对路径粘贴进远端 Shell。

  

## 5. 文件保存在哪里

  

```mermaid

flowchart TB

    V[Vault 相对路径]

    V --> N[projects/demo/readme.md]

    V --> P[assets/diagram.png]

  

    N --> WR[D:\TermyReceive\projects\demo\readme.md]

    P --> WP[D:\TermyReceive\assets\diagram.png]

  

    N --> UR[/home/user/TermyReceive/projects/demo/readme.md/]

    P --> UP[/home/user/TermyReceive/assets/diagram.png/]

```

  

| 目标系统 | 默认 Shell | 接收目录示例 |

| --- | --- | --- |

| Windows | PowerShell | `D:\TermyReceive` |

| Ubuntu Server | Bash | `/home/user/TermyReceive` |

  

目录结构保持不变，笔记中的相对附件引用仍可使用。同名文件会直接覆盖，不再逐项确认。

  

## 6. 用户会看到什么

  

```text

┌────────────────────────────────────────────────────────────┐

│ [本地 | 远程]  [目标设备 ▾]  ● 已连接     [断开]          │

├────────────────────────────────────────────────────────────┤

│                                                            │

│  原有 xterm.js 终端区域                                    │

│                                                            │

└────────────────────────────────────────────────────────────┘

```

  

| 情况 | 页面反馈 | 用户下一步 |

| --- | --- | --- |

| Agent 未运行 | 设备离线 | 在目标端启动 Agent |

| 登录失效 | 请重新登录 | 打开账号设置 |

| 设备已有会话 | 设备忙 | 结束旧会话后重试 |

| Shell 无法启动 | 终端启动失败 | 检查目标端 Shell 配置 |

| 接收目录不可写 | 无法写入 | 使用 Agent CLI 修改目录 |

| 网络中断 | 连接已中断 | 手动重新连接 |

| 传输中断 | 失败，部分文件可能已写入 | 检查后重新发送 |

  

## 7. V1 边界

  

```mermaid

flowchart LR

    subgraph YES[V1 已支持]

        Y1[Windows 控制端]

        Y2[Windows / Ubuntu Server 目标端]

        Y3[单个远程 Shell]

        Y4[笔记与直接附件]

        Y5[TLS 与设备归属校验]

    end

  

    subgraph NO[后续版本]

        N1[自动重连]

        N2[原子文件传输]

        N3[断点续传]

        N4[多会话]

        N5[其他平台]

    end

```

  

用户需要知道的限制：

  

1. 文件由云端实时中转，服务端能够接触转发内容；当前不是端到端加密。

2. 文件直接写入正式目录，传输失败时可能留下已完成或不完整文件。

3. 同名文件直接覆盖，不能自动恢复旧版本。

4. Agent 使用目标端普通用户权限，不提权。

  

## 8. 用户验收清单

  

```mermaid

flowchart TD

    A[Windows Termy 登录]

    B[配对 Windows 或 Ubuntu Server]

    C[目标设备显示在线]

    D[连接 PowerShell 或 Bash]

    E[命令输入输出正常]

    F[拖入笔记与直接附件]

    G[远端目录可读取]

    H[主动断开后 Shell 结束]

  

    A --> B --> C --> D --> E --> F --> G --> H

```

  

V1 通过需同时满足：

  

- Windows -> Windows 与 Windows -> Ubuntu Server 两条路径均完成上述闭环；

- Ubuntu 退出 SSH 后 Agent 仍在线；

- 其他账号无法发现或连接该设备；

- 本地终端及本地拖拽行为没有变化；

- 页面能明确显示连接和传输的成功或失败。
