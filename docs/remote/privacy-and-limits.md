# 隐私说明与已知限制

面向使用者。请在开始用远程功能前读一遍——有几条会影响你怎么用它。

---

## 1. 隐私

### 1.1 服务器能看到什么

**这不是端到端加密。** 你的终端输入输出、笔记正文和附件内容，在从控制端到目标机的路上会经过云端 Relay，**Relay 进程能够访问这些明文**。

链路本身是加密的（公网全程 TLS），但那是传输层加密：数据到了 Relay 会被解密、转发、再加密。运营 Relay 的人在技术上有能力读取转发中的内容。

### 1.2 服务器不保存什么

Relay **不持久化**任何正文：

- 终端命令和输出不落库、不写文件、不进日志
- 笔记与附件内容只做实时转发，不写云端数据库，也不留历史文件列表
- 会话与传输路由只存在于内存中，进程重启即消失

### 1.3 服务器保存什么

只有三张表：账号（登录名 + Argon2id 口令摘要）、配对码（摘要）、设备（名称、平台、Agent 版本、令牌摘要、最后在线时间）。

**没有任何机密以明文保存**：口令走 Argon2id，配对码和设备令牌走带服务器 pepper 的 HMAC-SHA-256。日志不记录配对码、访问令牌或设备令牌。

### 1.4 你应该做的

- 只连接你自己信任的 Relay
- 配对完成后，撤销没用上的配对码
- 不再使用某台设备时，在设备列表里解绑它

## 2. 已知限制

以下都是 MVP 有意接受的取舍，不是待修的缺陷。

### 2.1 连接与会话

**同一账号同时只能有一个 Obsidian 窗口连接。** 第二个窗口连上来会把第一个顶掉。

**终端会话不恢复。** 网络抖动、云端重启或 Agent 重连之后，远端的 shell 已经被终止，需要重新连接。正在运行的命令会随之结束。

**云端是单节点。** 服务端发版期间所有连接都会断开。Agent 会自动退避重连，Obsidian 端需要手动重连。

**访问令牌会过期，默认 15 分钟。** 过期后设备列表会失效并要求重新登录，但**当前已建立的连接不会断**——控制 WSS 只在握手时校验一次。没有 refresh token，插件也不保存密码，所以到期就得重新输一次。部署方可以用 `TERMY_ACCESS_TOKEN_TTL_SECS` 调整（见 [operations.md](operations.md) §1.2）；个人单用户部署建议设成 12 小时。

### 2.2 文件传输

**失败可能留下半个文件。** MVP 直接写入正式目录，没有临时区，也不做原子替换。传输中断时，已完成的文件会留下，正在写的那个文件会留下不完整的内容。UI 会提示这一点，但**不会自动清理**。

**传输期间不要编辑正在传的笔记。** 文件大小在预检时记录，传输时以实际读取的字节为准；中途编辑可能导致这次传输失败，需要重新拖入。

**同名文件直接覆盖**，没有确认提示，也没有备份。

**只传根笔记和它直接引用的非 Markdown 附件。** 不递归其他笔记——链接到的笔记不会被一起传过去。

**指向不存在笔记的链接会被静默忽略。** 这是有意的：Obsidian 里链接到尚未创建的笔记是常态。但如果链接看起来指向一个附件（带图片、PDF 等扩展名）却找不到文件，整次传输会被拒绝，因为传过去也是个坏文档。

**容量上限**：单文件 64 MiB，整次 256 MiB，最多 256 个文件。超出会在发送前被拒绝并告诉你具体是哪一项超了。

### 2.3 功能边界

- 控制端只支持 Windows 上的 Obsidian 桌面版
- 目标端只支持 Windows 和 Ubuntu Server
- 每台设备同时只能有一个远程终端；第二个请求会收到「设备忙」
- 不支持文件回传——只能从 Obsidian 传到目标机，反过来不行
- 不支持多人共享或协作控制
- 没有断点续传，也没有自动重试

### 2.4 安全边界

**Agent 和远程 shell 以绑定它的普通用户身份运行**，不提供提权。这意味着远程终端能做的事，等于那个用户能做的事——不多也不少。

**配对码没有过期时间。** 它是一次性的（用掉即失效）也可以主动撤销，但在被使用或撤销之前会一直有效。拿到配对码的人可以把任意一台机器绑到你的账号下。用完请撤销。

## 3. 出问题时

**远程终端连不上**——先看设备列表里它是否在线。不在线的话去目标机上 `termy-agent status`。

**远程终端里某个命令 command not found，但 SSH 进去却能用**——远程 shell 不是登录 shell。Ubuntu 把 `~/.local/bin` 加进 PATH 的那段在 `~/.profile` 里，而非登录 bash 只读 `~/.bashrc`，所以装在那儿的东西（pipx、cargo、npm 全局、Claude Code）全都找不到。新版 Agent 默认已是登录 shell；旧配置手动修：

```bash
termy-agent config set-shell /bin/bash -- -l   # 注意 -- ，否则 -l 会被当成 CLI 自己的选项
systemctl --user restart termy-agent
```

改的是**新会话**的 shell，已经开着的远程终端要关掉重开。

**目标机一直显示离线**——检查 Agent 是否在跑，以及它能否访问 Relay 的域名。`journalctl --user -u termy-agent -f`（Ubuntu）会给出重连失败的原因。

**传输失败**——错误消息会说明原因。常见的是接收目录不可写，或者附件路径在目标平台上不合法（比如文件名里有 Windows 不允许的字符）。

**退出 SSH 后 Agent 就停了**——lingering 没启用。见运维文档的 Ubuntu 安装部分。
